# 地形生成性能优化（Phase 12）

本轮目标：把 gorigional 的生成速度压到 main `Normal` 的 1.5–2 倍以内，同时不改变地形/洞穴形状。

## 12.1 性能剖面

优化前 seed 12345、9 区块平均：

| 阶段 | 耗时 |
|---|---:|
| `setBlocksInChunk` | 0.32s |
| `MapGenCaves` | 0.40s |
| `replaceBiomeBlocks` | 0.12s |
| 结构 prepare | 0.01–0.36s |
| 合计 | 0.925s/区块 |

洞穴占 43%，是主要瓶颈。

## 12.2 群系查表缓存

- `generateHeightmap()` 先把 10×10 群系的 `min/max elevation` 缓存到 ID 数组，避免 625 次静态查表。
- `replaceBiomeBlocks()` 按群系 ID 缓存 Biome 对象和颜色，避免每列重复调用 `getColor()`。
- 地形形状不变。

## 12.3 洞穴原点缓存

`MapGenCaves` 每个区块都会扫描 ±8 区块的洞穴原点，并对每个原点重建 MT19937、生成节点。
邻近区块会反复处理同一批原点。

现在：

1. 每个 origin 的洞穴节点/房间/顶层隧道参数按 `x:z` 缓存。
2. 无洞穴的 origin 缓存为 `null`。
3. 缓存命中时只执行 carve，不再重建随机数和节点。
4. 世界种子的两个乘子只计算一次。
5. `addTunnel` 的分支、形状、随机流保持原实现。

验证：与优化前的 `MapGenCaves` 对比，4 组种子/坐标的整区块方块数组 `diff=0`，洞穴完全一致。

## 12.4 实测结果

同一设备、seed 12345、仅 `generateChunk`：

| 区块数 | 优化前 | 优化后 |
|---:|---:|---:|
| 9（3×3） | 7.5–8.6s | 5.2–5.4s（0.58–0.60s/块） |
| 25（5×5） | 19.9–21.6s | 13.7–14.0s（0.55–0.56s/块） |

完整生成 + populate：

| 区块数 | 生成 | populate | 合计 |
|---:|---:|---:|---:|
| 9 | 5.20s | 2.77s | 7.96s（0.88s/块） |
| 25 | 13.97s | 8.19s | 22.16s（0.89s/块） |

对比 main `Normal`：

| 场景 | main | gorigional |
|---|---:|---:|
| 9 区块生成 | 4.09s（0.45s/块） | 5.2–5.4s（0.58s/块） |
| 25 区块生成 | 7.52s（0.30s/块） | 13.7–14.0s（0.55s/块） |

25 区块生成约为 main 的 **1.8 倍**，达到目标；完整生成约 **0.89s/块**。
